# Skyline Garden: design for Milestone 3 (exploration, feel, onboarding) and Milestone 5 (PWA and Capacitor)

This design is built on the code at commit `b971689`. It follows the existing rules:

- Every action is a pure function `(state, …args, now) → {ok, state, events} | {ok:false, error}` that runs on a `structuredClone` through `commit()`.
- `src/game` imports nothing from three, Preact, render, UI or core.
- The UI is built from signals and listens to `game.events`.
- 3D is procedural, with shared toon materials and cached geometries.
- Saves are versioned through the `MIGRATIONS` map in `src/game/save.ts`.

## 0. Key decisions

| Topic             | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mine view         | A separate three `Scene` that shares the one `WebGLRenderer`. It is lazy-loaded (`import()`), reached from a floating "Cloudrock Quarry" island under floor 0 and from a side-rail button. It is also the tutorial guide, so its arrival at level 4 continues the same story.                                                                                                                                                                                                                                                                       |

## 1. Shared prerequisites and the contract with M2

### 1.1 What M3 assumes M2 delivers

If M2 lands with different names, only M3's config tables change. The logic stays the same.

| Assumed from M2                                                                                                                          | Used by M3 for                                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `state.materials: Counts<MaterialId>`, where `MaterialId` includes `'stone' \| 'clay' \| 'iron' \| 'crystal'` (pot-forge inputs)         | Mine loot, pickaxe upgrade costs, pet trip loot                                  |
| `GoodId` machine goods                                                                                                                   | `MINE_SNACKS` (goods that restore energy) and pet food                           |
| Pests: a bug record with a spawn timestamp `at`, an action `catchBug(state, floor, slot, now)` and an event `bugCaught {floor, slot, …}` | The pet catches bugs automatically; SFX `bugCatch`; stat `bugsCaught`            |
| Daily quests: a `dayIndex(now)` helper; `machineDone`/`goodsCollected`, `potForged`, `balloonSent`, `questCompleted` events              | Mine daily reset; SFX; achievement stats                                         |
| A Reward type and `grantReward()` helper (daily quests and the balloon need one)                                                         | Mine loot, chests, trips, achievements and tutorial all grant rewards through it |
| Final `SAVE_VERSION = V`                                                                                                                 | M3 migrations are V→V+1 through V+4. If M2 ends at 2, M3 uses versions 3 to 6.   |

If M2 hasn't created them, M3 creates these. If it has, they are reused:

- **`src/game/day.ts`**: `DAY_OFFSET_MS = 7*3600_000` (the day boundary is midnight UTC+7 for every player, so the server agrees), `dayIndex(now)` and `msUntilNextDay(now)`.
- **`src/game/rewards.ts`**:
  - `interface Reward { gold?: number; ruby?: number; xp?: number; seeds?: Counts<PlantId>; materials?: Counts<MaterialId>; consumables?: Counts<ConsumableId> }`
  - `grantReward(draft, reward, now, events)`. This calls `addXp`, so a level-up can happen.
- **`src/game/commit.ts`**: `fail`, `commit` and `isPositiveInt` move out of `actions.ts` so that `mine.ts`, `pet.ts` and other files share them. `commit()` gets a fixed post-commit pipeline:
  ```ts
  export function commit(state: GameState, mutate: (d: GameState, ev: GameEvent[]) => void): ActionResult {
    const draft = structuredClone(state);
    const events: GameEvent[] = [];
    mutate(draft, events);
    recordStats(draft, events); // stats.ts  (M3)
    tutorialOnEvents(draft, events); // tutorial.ts (M3)
    // progressQuests(draft, events);    // M2 daily quests, if they are event-derived
    checkAchievements(draft, events); // achievements.ts (M3); runs last and appends events
    return { ok: true, state: draft, events };
  }
  ```
  This is a single pass. Events appended by these hooks (`achievementUnlocked`, `tutorialStep`) are not fed back into the stats.
- **`ACTION_ERRORS` constant array** in `types.ts`, with `type ActionError = (typeof ACTION_ERRORS)[number]`. A test can then assert that every error has a vi and an en message.
- **Determinism guard (ESLint)** for `src/game/**`: `no-restricted-properties` on `Math.random` and `Date.now`. The one existing default parameter in `createNewGame` gets an inline disable. This keeps M3 logic replayable on the M4 server.

### 1.2 Delivery order and save versions

Each commit that changes the shape of GameState bumps `SAVE_VERSION` by 1. A migration is never edited after it is pushed, because CI deploys every push to Pages and real saves exist at every intermediate version.

| #   | Commit                                                                                           | GameState change        | SAVE_VERSION |
| --- | ------------------------------------------------------------------------------------------------ | ----------------------- | ------------ |
| 3.0 | Save hardening: load status, backups, tab lock, export/import (pure)                             | none                    | V            |
| 3.1 | Settings store, locale signal, `en.ts`, SettingsPanel, side rail, ConfirmDialog                  | none                    | V            |
| 3.2 | Audio engine, SFX, generative music, haptics                                                     | none                    | V            |
| 3.3 | Render infra: ScreenHost/Screen refactor, FrameScheduler, Quality, `three` chunk                 | none                    | V            |
| 3.4 | Stats and achievements                                                                           | `stats`, `achievements` | V+1          |
| 3.5 | Tutorial and feature tips                                                                        | `tutorial`              | V+2          |
| 3.6 | Mine, consumables, quarry island                                                                 | `mine`, `consumables`   | V+3          |
| 3.7 | Pet                                                                                              | `pet`                   | V+4          |
| 3.8 | PWA, procedural icons, update prompt, install button                                             | none                    | V+4          |
| 5.1 | Capacitor config, `src/platform/native.ts`, safe-area CSS, `build:native`, optional APK workflow | none                    | V+4          |

Dependencies:

- 3.0 must come before 3.8: the PWA update path can lose saves without it (see §2).
- `commit.ts` must exist before 3.4 and 3.5.
- 3.1 must come before 3.2 and 3.3, because volume and quality come from settings.
- 3.3 must come before 3.6, which needs ScreenHost.
- 3.5 must come before 3.6 and 3.7, which use the feature-tip framework.
- 3.6 must come before 3.7: trips grant consumables, and treats drop in the mine.
- 3.7's bug catching needs M2 pests. It is behind `if (hasBugs(state))`, so it is a no-op otherwise.
- 3.8 comes after 3.3, so the lazy chunk names are final before precaching.

Each step is gated on: `npm run typecheck && npm run lint && npm test && npm run build && npm run e2e`.

## 2. Step 3.0: Save hardening (prerequisite for PWA and import)

**Existing bug that becomes a data-loss risk with a PWA.** `deserialize()` returns `null` both for a corrupt save and for one whose `version > SAVE_VERSION`. `Game` then calls `createNewGame` and autosaves over the real save. A stale service-worker tab (or a second tab running old code) will therefore wipe progress.

Changes in `src/game/save.ts` (pure):

```ts
export type LoadResult =
  | { status: 'none' }
  | { status: 'ok'; state: GameState; migratedFrom: number | null }
  | { status: 'corrupt'; raw: string }
  | { status: 'tooNew'; version: number };
export function readSave(json: string | null): LoadResult;
export const SAVE_BACKUP_KEY = 'skyline-garden/save.backup'; // the save as it was before migration or reset
export const SAVE_CORRUPT_KEY = 'skyline-garden/save.corrupt';
export function exportSave(state: GameState, now: number): string; // {format:'skyline-garden-save', exportedAt, save}
export function importSave(text: string): LoadResult; // accepts the wrapper or raw state JSON; migrates; validates
```

- `loadGame()` stays as a thin wrapper so existing tests still pass.
- `looksValid()` gets mild checks for each new field:
  - `stats` and `achievements` are records;
  - `tutorial.step` is a string;
  - `mine` is null, or has a `tiles` array of length `MINE_COLS*MINE_ROWS`;
  - `pet` is null or a record.

Changes in `src/core/Game.ts`:

- `readonly blocked = signal<null | 'tooNew' | 'otherTab'>(null)`. When it is set, `save()` does nothing.
- In the constructor:
  - `corrupt`: copy the raw JSON to `SAVE_CORRUPT_KEY`, start a new game and show a toast.
  - `tooNew`: set `blocked='tooNew'`. A blocking notice explains that an update is needed and has a reload button that triggers the SW update.
  - `migratedFrom != null`: write the raw pre-migration JSON to `SAVE_BACKUP_KEY` before the first save.
- `replaceState(next: GameState)` is used by import:
  1. reset `clock.offsetMs`;
  2. clear the UI signals;
  3. set the state;
  4. call `update()`;
  5. call `save()`.
- New file **`src/core/tabLock.ts`**: a `BroadcastChannel('skyline-garden')` handshake. When a newer tab announces itself, the older tab sets `blocked='otherTab'` and stops autosaving, with the overlay "Game đang mở ở tab khác".

## 4. Step 3.2: Procedural audio (`src/audio/`)

```
src/audio/AudioEngine.ts    AudioContext lifecycle, buses master→{sfx, music(+reverb)}, unlock, suspend/resume, volume, voice limit
src/audio/synth.ts          primitives: playTone, playNoise (cached 1 s white-noise buffer), envelopes, makeImpulse() (procedural reverb IR)
src/audio/sfx.ts            SFX_RECIPES: Record<SfxId, SfxRecipe> (data) + playSfx(engine, id, {pitch})
src/audio/music/composer.ts PURE: composeBar(rng, theme, barIndex) → NoteEvent[]   (unit-tested)
src/audio/music/themes.ts   garden + mine theme definitions
src/audio/music/MusicPlayer.ts  lookahead scheduler (setInterval 100 ms, schedules 0.3 s ahead on ctx.currentTime), instruments, crossfade
src/audio/connectAudio.ts   AppEvent → SFX; global button-click listener; panel open/close whoosh; screen → theme
```

ESLint: `src/audio/**` may not import three or render.

### 4.1 Engine

- The context is created lazily with `latencyHint:'interactive'`.
- **Mobile unlock.** Capture-phase, run-once listeners on `pointerup`, `touchend` and `keydown`. They call `ctx.resume()` and start a silent one-sample buffer; iOS requires both to happen inside a user gesture. Set `navigator.audioSession.type='ambient'` when it exists (Safari 17+): the game then respects the silent switch and mixes with the player's own music.
- Suspend the context on `visibilitychange:hidden` and on the Capacitor `pause` event. Resume on visible. Also resume on the next touch if iOS reports `state==='interrupted'`.
- Gain is `v²` (perceptual). Use `setTargetAtTime` to avoid clicks. Mute ramps master to 0.
- Voice limit: at most 32 sources at once. Per-recipe `cooldownMs`, default 30. While dragging, combo pitch steps along a pentatonic scale and resets 600 ms after the last event.
- Debug hook: `engine.log: SfxId[]` (last 50), exposed as `__skyline.audio.log`.

### 4.2 SFX recipe format and table

      type: 'tone';

      f0: number;
      f1?: number;
      at?: number;
      dur: number;

      gain: number;
      vibrato?: [rateHz: number, depthHz: number];

  | { type: 'noise'; at?: number; dur: number; gain: number; filter: Filter & { freq1?: number } }

interface SfxRecipe {

### 4.3 Generative music

- **Garden theme**:
  - F-major pentatonic (F G A C D), 70 BPM, bars of 4 beats.
  - Chords Fmaj7 → Dm7 → B♭maj7 → C6sus, 2 bars each.
  - Pad: 3 detuned (±4 cents) triangle/sine voices, attack 2 s / release 3 s, lowpass 900 Hz with a 0.05 Hz LFO of ±300 Hz on the cutoff, gain 0.05.
  - Melody ("kalimba": sine plus 2× partial at 30%, attack 5 ms, exponential decay 1.2 s):
    - a note on each eighth with probability 0.28 (0.1 on the beat where the chord changes);
    - a random walk of ±1–2 scale steps between C5 and C7, preferring chord tones on strong beats;
    - random pan within ±0.4;
    - feedback delay 0.43 s at 0.3.
  - Bass: sine root on beat 1, decay 2 s, gain 0.06.
  - Every 4th bar, a 3-note wind-chime sparkle.
- **Mine theme**:
  - D dorian, 60 BPM, a darker pad (lowpass 600).
  - "Water drip" plinks: sine with a downward pitch bend, probability 0.15.
  - Rumble drone: noise lowpass 120 Hz, gain 0.02.
- The music bus goes through a ConvolverNode with a procedural impulse response (2 s of stereo noise with exponential decay). The reverb is skipped when quality is `low`.
- `composeBar(rng, theme, bar)` is pure and seeded with `Rng` from `src/game/rng`. `MusicPlayer` only renders the NoteEvents it returns. Music starts after unlock, crossfades over 1.5 s when the screen changes, and is skipped entirely when `music===0 || muted`.

### 4.4 Haptics

`src/platform/haptics.ts` exports `haptic('light'|'medium')`:

- native: `@capacitor/haptics`;
- web: `navigator.vibrate?.(8|20)`.

It is triggered on `planted`, `harvested` and `mineBroken`, and only when `settings.haptics` is on.

## 5. Step 3.3: Render infrastructure and performance

### 5.1 Screens

Refactor `main.tsx` and `InputController` so that a garden screen and a mine screen can share one renderer.

```ts
// src/render/screens/Screen.ts
export type ScreenId = 'garden' | 'mine';
export interface Screen {
  readonly id: ScreenId;
  readonly scene: Scene;
  readonly scroller: CameraScroller;
  readonly input: ScreenInput;
  update(dt: number, now: number, time: number): boolean; // true = something is animating
  enter(): void;
  exit(): void;
}
export interface ScreenInput {
  begin(x: number, y: number): 'tool' | 'pending'; // 'tool' captures the drag (garden tools); otherwise tap/scroll is decided by distance
  toolMove?(x: number, y: number): void;
  tap(x: number, y: number): void;
}
```

- **`SceneManager`** keeps the renderer, camera and fit logic.
  - The lights move into the helper `addDefaultLights(scene)`.
  - `render(scene)` takes the active scene.
  - `project()` stays.
  - `focusY` becomes per screen: each screen's scroller saves and restores it in `exit` and `enter`.

### 5.2 `src/render/FrameScheduler.ts` (render only when needed)

The main loop still runs `update` every rAF: logic, `scroller.update` (camera) and tweens. That is cheap JS and keeps e2e `slotScreenPosition` stable. `renderer.render` is gated:

```ts
shouldRender(time, animating): boolean
  dirty                      → render   // set by an effect on game.state, ui.selected, ui.screen, locale, resize
  time < activeUntil         → full rate // wake(1500) on pointer, wheel, any AppEvent, tween/particle/scroller motion
  animating                  → ambient rate: high 60, medium 30, low or batterySaver 20; 15 while a Sheet panel is open
  otherwise                  → skip
```

"Animating" comes from the screen. In the garden it means ready plants swaying, particles, the selection ring pulsing or the pet bobbing. The background cloud drift counts as ambient.

### 5.3 `src/render/Quality.ts`

| Tier   | DPR cap | antialias | Particle count | Background clouds | Reverb |
| ------ | ------- | --------- | -------------- | ----------------- | ------ |
| low    | 1       | false     | ×0.5           | 8                 | off    |
| medium | 1.5     | true      | ×1             | 18                | on     |
| high   | 2       | true      | ×1             | 18                | on     |

- `auto` starts at `medium` when `matchMedia('(pointer: coarse)')` matches, or when `hardwareConcurrency ≤ 4` or `deviceMemory ≤ 4`; otherwise `high`.
- While active, it measures rAF deltas over 3-second windows. Average > 1.5× the target interval lowers DPR by 0.25, down to 1. Below 0.8× for 10 s raises it back up to the cap.
- `antialias` and `powerPreference` (`'default'` on mobile, `'low-power'` on low) can only change when the renderer is recreated, so they apply on the next load and the settings panel says so.
- `?debug&perf` shows an FPS, draw-call and DPR overlay read from `renderer.info`.

### 5.4 Bundle

- `vite.config.ts` → `build.rolldownOptions.output.codeSplitting = { groups: [{ name: 'three', test: /node_modules[\\/]three/ }, { name: 'preact', test: /node_modules[\\/](preact|@preact)/ }] }`. In Vite 8 / Rolldown, `manualChunks` and `advancedChunks` are deprecated in favour of `codeSplitting`.

### 8.3 Logic: `src/game/mine.ts` (pure)

- `generateMine(rng, day): MineTile[]` is deterministic.
- `tileIndex(x, y)`, `neighbors`.
- `isReachable(tiles, x, y)`: true when `y===0`, or when any of the 4 neighbours is broken.
- `mineEnergy(m, now) → { energy, nextAt }`. It is computed from timestamps, keeps partial regen progress when spending, guards against the clock going backwards with `max(0, …)`, and regen stops at or above max (refills may exceed max).
- Actions:
  - `openMine(state, now)`:
    - `LEVEL_TOO_LOW` below the unlock level;
    - if `mine===null` or `day!==dayIndex(now)`, draws a new grid from `state.rngSeed`, resets `refillsToday` and tops up energy;
    - emits `mineOpened {day, fresh}`;
    - otherwise it is a no-op that returns the same state.
  - `digTile(state, x, y, now)`. Validation order:
    1. `MINE_EXPIRED` if the day is stale. The UI then re-runs `openMine` and shows the toast "Mỏ đã làm mới!".
    2. `INVALID` if out of bounds.
    3. `TILE_BROKEN`.
    4. `TILE_UNREACHABLE`.
    5. `NO_ENERGY`.
    6. `STORAGE_FULL` if M2 caps materials.

    Then it spends 1 energy and lowers `hp` by the pickaxe damage. It emits `mineHit {x, y, hp}`; on break it calls `grantReward(loot)` and emits `mineBroken {x, y, kind, loot}`; on a chest it also emits `mineChest {reward}`.

  - `useBomb(state, x, y, now)`: `NO_BOMB`; the centre must be reachable. Breaks the 3×3 area ignoring hardness, costs no energy, grants all loot, emits `mineBomb {x, y, broken[]}`.
  - `refillEnergy(state, now)`: ruby, `NOT_ENOUGH_RUBY`.
  - `useSparkTea(state, now)`.
  - `eatSnack(state, goodId, now)`.
  - `upgradePickaxe(state)`: `MAX_TIER`, `LEVEL_TOO_LOW`, `NOT_ENOUGH_GOLD`, `NOT_ENOUGH_MATERIALS`; emits `pickaxeUpgraded {tier}`.

New errors: `NO_ENERGY`, `MINE_EXPIRED`, `TILE_UNREACHABLE`, `TILE_BROKEN`, `NO_BOMB`, `MAX_TIER`, plus `NOT_ENOUGH_MATERIALS` if M2 doesn't add it.

## 14. Risks

1. **Save loss through a stale PWA or a second tab.** This is a real bug today. Mitigated by step 3.0, which must ship before 3.8.
2. **iOS storage eviction.** Safari deletes localStorage for sites that aren't installed after 7 days without use. Mitigations: install prompt, `storage.persist()`, an export reminder in settings, and M4 cloud save. Document it in the README.
3. **Tutorial soft-lock or blocked e2e.** The skip button is always present; the overlay hides behind modals; the tutorial order is injected so no step depends on random orders; e2e skips the tutorial by default.
4. **Dependence on M2 names.** Isolated to config tables (`MINE_SNACKS`, loot `MaterialId`s, pet bug catching behind `hasBugs`). Agree the contract in §1.1 with the M2 design before 3.6 and 3.7. The Reward helper and `commit.ts` should land in M2 if possible.
5. **Camera bounds changing when the quarry is added** (initial view and e2e coordinates). Fixed by `CameraScroller.homeY`.
6. **Render-on-demand.** The camera and logic must still update every frame. Only `renderer.render` is skipped, so `slotScreenPosition`, which waits on rAF in e2e, stays valid.
7. **iOS audio quirks** (silent switch, the "interrupted" state after calls). Handled by `audioSession` 'ambient' and resuming on touch or visibility. Manual testing on a device is needed.
8. **Android WebView safe-area values.** Relies on Capacitor 8 `SystemBars` CSS injection; verify on the user's device. The orientation lock uses a plugin because native projects aren't committed.
9. **Cheating with export/import.** Fine offline: it is the player's own data. In M4 the server is authoritative, and an imported local save can't overwrite the cloud save without server-side replay or validation. Flag this to the M4 design.
10. **Daily reset timezone.** A fixed UTC+7 boundary, shared with M2 quests and the M4 server. English-speaking players get the reset at 17:00 UTC, which is acceptable and documented.
11. **Performance on SwiftShader in CI** with a second scene. Keep the mine instanced (fewer than 15 draw calls for tiles) and lazy; `Quality` `auto` may lower DPR in CI, which tests don't depend on.
12. **Content balance.** The loot and pet numbers are first guesses. The Monte-Carlo economy test keeps them inside bounds relative to farming income; tune after playtesting.
13. **README roadmap.** The earlier "GLTF models" item for M3 is replaced by the user's decision that everything is procedural. Update the README and the plan.
